# PranVayu: data contracts

Contract-first: the frontend and backend both build against these shapes. Save one real payload as `web/public/mock/<locality>.json` on day one so the frontend never waits for AWS.

## 1. External sources

Names marked "verify" must be checked in Phase 0 against the live docs before code depends on them.

### Open-Meteo weather (winds, boundary layer)
- Endpoint: `https://api.open-meteo.com/v1/forecast`
- Parameters: `latitude` and `longitude` as comma-separated lists (batch the 121 grid points into 4 requests); `hourly` = wind speed and direction at 975, 950 and 925 hPa and at 10 m, plus boundary layer height; `wind_speed_unit=ms`; `models=ecmwf_ifs025` (verify pressure-level support; fallback `gfs_seamless`); `past_hours=72`; `forecast_hours=72`; `timeformat=unixtime`.
- Variable names to verify: `wind_speed_975hPa`, `wind_direction_975hPa` (and 950, 925), `wind_speed_10m`, `wind_direction_10m`, `boundary_layer_height`.
- Free tier: non-commercial; 600 calls/min, 5,000/h, 10,000/day, 300,000/month. Attribution required (CC BY 4.0).

### Open-Meteo air quality (CAMS)
- Endpoint: `https://air-quality-api.open-meteo.com/v1/air-quality`
- Parameters: receptor coordinates; `hourly=pm2_5,pm10`; `domains=cams_global`; `past_hours=48`; `forecast_hours=72`; `timeformat=unixtime`.
- Resolution about 45 km, 3-hourly, updated every 12 h. Attribute CAMS and Open-Meteo.

### NASA FIRMS
- Endpoint pattern: `https://firms.modaps.eosdis.nasa.gov/api/area/csv/<MAP_KEY>/<SOURCE>/<west,south,east,north>/<DAY_RANGE>[/<DATE>]`
- Sources for live: `VIIRS_SNPP_NRT`, `VIIRS_NOAA20_NRT`, `VIIRS_NOAA21_NRT`. For archives: `VIIRS_SNPP_SP`, `VIIRS_NOAA20_SP` with a date.
- Day range 1 to 5 per call. Limit 5,000 transactions per 10 minutes. Free MAP_KEY.
- Columns used: latitude, longitude, acquisition date and time, confidence, FRP. Check the attribute tables for exact column names and confidence coding.

### OpenAQ v3
- Base: `https://api.openaq.org/v3`, header `X-API-Key`. Limits 60/min, 2,000/h. Coverage uneven; stations go stale.
- Needed: find locations near a coordinate (the Delhi bbox), list a location's sensors (PM2.5, PM10), latest value, hourly history for replay. Endpoint names to verify: locations, locations/{id}/latest, sensors/{id}/hours or measurements. Look up parameter ids via the parameters endpoint.
- Always check the timestamp on a reading before treating it as current.

## 2. Config files

`config/localities.json` (array): `id` (slug), `name_en`, `name_hi`, `lat`, `lon`, `openaq_location_id`, `station_name`, `elevation_m`.

`config/model.yaml`: every parameter in 04-ALGORITHMS section 9, plus `bias_mode` and `models` preference list.

`config/thresholds.yaml`: activity types with Go and Limit upper bounds, activity window minutes, confidence-to-decision-value mapping.

`config/timetable_defaults.json`: periods with `id`, `label_en`, `label_hi`, `time` (HH:MM), `activity_type` (light or strenuous).

`config/grap.json` (manual): `stage` (none, I, II, III, IV), `effective_date`, `source_url`, `updated_at`. Missing or older than 7 days means the app shows "Check the latest CAQM order".

Generated by evaluation: `config/smoke_levels.json` (q50, q85 cut points, calibration window, `generated_at`), `config/bands.json` (p10 and p90 factors by lead bucket, window, `generated_at`).

## 3. Internal API

Base: API Gateway HTTP API. All responses JSON, `Cache-Control: max-age=300`, `schema_version` field present.

| Route | Purpose |
|---|---|
| GET `/v1/localities` | List of localities (id, names, lat, lon) |
| GET `/v1/forecast?locality=<id>` | Live payload |
| GET `/v1/forecast?locality=<id>&replay=<run_id>&asof=<ISO>` | Replay payload from S3 |
| GET `/v1/replay` | Available replay runs: id, window start and end, as-of grid |
| GET `/v1/evidence?run=<id>` | Evaluation output (section 5) |
| GET `/v1/health` | Source ages and last model-run time |
| P1 POST `/v1/telegram` | Bot webhook |

Errors: `{ "error": "<code>", "message": "<plain sentence>" }` with a 4xx or 5xx status. Codes: `unknown_locality`, `no_data_yet`, `replay_not_found`.

```
{
  "schema_version": 1,
  "mode": "live" | "replay",
  "replay": { "run_id": "...", "window": ["2025-..", "2025-.."] } | null,
  "generated_at": "2026-10-10T10:25:00Z",
  "as_of": "2026-10-10T10:00:00Z",
  "locality": { "id": "dwarka", "name_en": "Dwarka", "name_hi": "द्वारका",
                "lat": 28.59, "lon": 77.05, "station_name": "..." },
  "freshness": { "fires_at": "...", "winds_run": "...", "obs_at": "...", "cams_run": "..." },
  "flags": ["uncalibrated", "stale_obs", "partial_data"],
  "days": [
    {
      "date": "2026-10-13",
      "confidence": "medium",
      "verdicts": [
        { "period_id": "assembly", "time": "07:45", "activity_type": "light",
          "verdict": "skip", "decision_value": 96,
          "range": { "p10": 74, "p50": 88, "p90": 112 },
          "category": "poor", "threshold_used": { "go": 60, "limit": 90 } }
      ],
      "clean_window": { "from": "15:00", "to": "17:30", "kind": "best" | "least_bad" }
    }
  ],
  "series": [
    { "t": "2026-10-10T10:00:00Z", "p10": 70, "p50": 85, "p90": 110, "observed": 82 }
  ],
  "drivers": [
    { "type": "regional_smoke", "level": "moderate", "confidence": "medium",
      "eta": { "from": "2026-10-13T08:30:00Z", "to": "2026-10-13T14:30:00Z" },
      "evidence": { "fire_clusters": 5, "wind_dir_950_deg": 310, "probability_peak": 0.62 } },
    { "type": "local_trapping", "confidence": "high",
      "evidence": { "hours": ["05:00", "09:00"], "blh_m": 260, "wind10_ms": 1.2 } }
  ],
  "smoke": {
    "present_now": false,
    "level_series": [ { "t": "...", "p": 0.31, "level": "low" } ],
    "fires": [ { "lat": 30.9, "lon": 75.2, "frp": 12.4, "t": "..." } ],
    "paths": [ { "level_hpa": 950, "points": [ [28.59, 77.05], [29.1, 76.2] ], "tick_hours": 12 } ]
  },
  "grap": { "stage": "II", "effective_date": "...", "source_url": "...", "stale": false },
  "text": { "en": ["..."], "hi": ["..."] } | null
}
```

Rules:
- Times are ISO 8601 UTC in the payload; the frontend formats in Asia/Kolkata.
- Numbers are rounded for display fields (PM2.5 to whole numbers), never in storage.
- `smoke.paths`: at most three (one per level, median path), at most 60 points each.
- `smoke.fires`: at most 800, highest FRP first.
- Payload under 60 KB gzipped for one locality.
- The payload contains no language-specific headline. The client builds it.

## 6. DynamoDB and S3 keys

- `pv-state`: `pk = LOC#<locality_id>`, `sk = LATEST`, `payload`, `generated_at`, `schema_version`.
- `pv-subs` (P1): `pk = CHAT#<id>`, `locality`, `created_at`, `last_sent_on`. Delete on stop.
- S3 keys: see 03-ARCHITECTURE section 5.

## 7. Fixtures

Save trimmed real responses for each source (one live window, one peak-season replay window) under `backend/tests/fixtures/`. Tests never call the network. One fixture must contain a missing-station case and one a stale-wind case, so degradation paths are tested.
